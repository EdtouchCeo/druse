# 학종 전략실 화면

**분석·전략 보고서:** 학생부 분석 자료만으로 미리보기와 PDF 저장을 할 수 있습니다. 교사 전략·학생 상담은 필수가 아닙니다. 상담 후 전략은 같은 메뉴의 **학습·진로 전략 보고서**에서 작성합니다. [사용 흐름과 검증](../../docs/53-analysis-and-strategy-reports.md). 로컬 소스와 빌드에 반영했으며 운영 배포 전입니다.

로컬 소스에는 [교사용 분석 문서 정리](../../docs/52-structured-teacher-report.md)를 추가했습니다. 여러 구간의 AI 분석을 종합하고 교사용 PDF의 현재 전략·실행 과제와 상세 근거를 구분합니다. 이 변경의 실제 모델 재분석·운영 배포는 아직 수행하지 않았습니다.

교사용 이용 순서와 문제 해결은 [학종 전략실 교사용 이용안내](../../docs/학종_전략실_교사용_이용안내.md)를 참고합니다. 배포된 화면의 **사용안내**에서도 같은 순서의 안내를 볼 수 있습니다.

현재 구현 버전은 **0.6.2**입니다. 로컬 분석의 인용 연결과 모델 오류 구분을 보완하고, PDF 드래그 첨부와 항목의 학년도·학년·학기·학교급 확인 저장을 추가했습니다. 원문은 보존하고 기간 정정 후에는 분석·문체 검토를 다시 진행합니다. 중1~고3 학생부의 읽힌 부분을 분석할 수 있으며 학교 추천 과제·동아리 자료의 고1·고2 대상 범위는 유지합니다. 상세 절차는 8쪽 교사용 매뉴얼과 HTML 안내에 정리했습니다. **학종 전략실** 이름과 대륜 교표 원본을 유지합니다.

학생 문서는 **안내 → 실행과제·기한·상태 → 다음 점검 → 방향·강점·보완점 → 교과·탐구·활동 계획** 순서입니다. 학생 결과물 미리보기는 저장·확정·공개와 구분하며, 학교 조건·AI 제한·출처와 미정 일정을 보존합니다. 분석 화면의 제안 시간 상한은 학생의 확인된 가용 시간을 늘리지 않습니다. 가용 시간 0분과 미입력을 구분합니다.

교사가 학생 자료를 분석해 먼저 전략을 수립하고, 이후 학생 상담을 반영해 최종 결과물을 만드는 Vue 3·TypeScript 화면입니다. **자료·분석 → 교사 전략 수립 → 학생 상담·반영 → 분석·전략 보고서** 순서로 진행합니다. 관심·학습 경험·활동·성적과 학교 자료를 입력하면 관찰 근거, 교사가 선택할 계획 제안, 적용 전 확인할 자료를 보여 줍니다. 상담 질문은 그 계획을 대조하는 참고 자료입니다.

전략 준비 완료는 서버가 현재 제목·전략·실행과제의 사본을 보존하는 절차입니다. 이후 실제 학생 반응·합의한 방향·수정 사항을 기록하고 현재 전략을 조정합니다. 상담 완료 후 문체 검토·교사 확정·명시적 학생 안내를 진행합니다. 준비 사본과 상담 기록은 학생 화면·PDF·JSON에 포함하지 않으며 단계와 권한을 API에서도 검사합니다.

학생은 안내된 최종 전략만 읽고 학생용 PDF로 저장합니다. 로컬 학생부 분석·파생 전략은 로컬에 보관하고 확정 후 학생 안내 PDF를 직접 전달합니다. 교사용 PDF는 사전 전략·상담 기록·최종 전략을 대조하는 용도입니다. 다음 회차로 개정할 때 기본자료·이전 전략·미완료 과제를 이어받고 사전 준비와 상담은 새로 시작합니다. 전체 절차는 프로젝트의 `docs/43-counseling-user-guide.md`와 `docs/47-student-understanding-dashboard.md`를 참고합니다.

학교 자료는 검토한 과제 111개·동아리 29개·활동 28개의 정적 묶음입니다. 학년·학년도·실제 선택 과목이 맞는 평가계획을 우선 표시하고 실제 시행·정정 여부는 별도로 확인합니다. 중학생은 탐색 자료로 표시합니다. `src/data/school-context.json`은 `counseling_local/data/school-context.json`과 바이트가 같아야 통합 복사할 수 있습니다. 원본 학교 PDF나 개인 정보가 든 자료를 자동 수집하지 않습니다.

## 실행과 빌드

대륜고 사용 설명서의 `output/web/index.html`을 화면 스타일 기준으로 사용합니다. 파랑 `#2a5298`·밝은 파랑 `#4a7bc4`·금색 `#e8a020`, 배경 `#f8fafc`·본문 `#0f172a`·경계 `#e2e8f0`와 같은 글꼴 구성을 따릅니다. 학교 교표는 사용 설명서의 `logo.png` 원본을 `src/assets/school-logo.png`에 포함해 로컬에서도 외부 이미지 요청 없이 표시합니다. 헤더와 복귀 경로는 학교 서비스의 소속을 드러내고 작업 도구는 별도 행에 배치합니다. 기존 확정 기록의 해시와 학생 공개 범위를 보존하며 새 회차에는 사전 전략 준비·학생 상담·최종 결과물 절차를 적용합니다.

Node 22.12 이상에서 이 폴더를 작업 위치로 사용합니다.

```powershell
npm ci --ignore-scripts
npm run dev
npm run build
npm test
npm run test:ui
```

개발 서버는 `127.0.0.1`로만 열리며 `/api`를 로컬 서버 `127.0.0.1:8765`로 연결합니다. 빌드 결과는 `dist/`이고 서비스 경로는 `/counseling/`입니다. 로컬 Python 서버가 이 빌드를 제공하거나, 통합 배포 단계에서 사용설명서의 같은 경로로 복사합니다. 이 폴더의 빌드는 자동 배포하지 않습니다.

기존 평가 작성 앱의 고정 package/lock 버전, OKLCH 색상 토큰, JSON 파일 백업·인쇄 패턴을 재사용했습니다. OneDrive 작업 폴더에서 전체 재귀 삭제를 피하도록 Vite `emptyOutDir: false`를 유지합니다. 배포 시에는 현재 `dist/index.html`이 참조하는 빌드를 사용합니다.

## 연결 방식

학교 회원 승인이 완료된 교직원은 별도 상담 참여 승인 없이 전략실을 이용합니다. 사용설명서에서 전략실로 들어가면 같은 `dr_sess_v1` 세션을 이어받고, 만료된 액세스 토큰은 공유 갱신 토큰으로 자동 갱신합니다. 재인증이 필요한 경우 온라인 전략실의 **로그인하고 전략실로 이동**은 같은 탭에서 학교 계정 인증을 시작하고 완료 후 `/counseling/`로 자동 복귀합니다. 만료된 세션은 갱신·재인증하며 복귀 경로는 전략실로만 제한하고 한 번 사용하면 지웁니다. 일반 사용설명서 로그인은 기존 경로를 유지합니다. 로컬 PC 연결은 별도 로그인 탭을 사용하며, 원래 연결 창에서 로그인 상태를 다시 확인한 뒤 **이 PC 연결**을 눌러야 합니다.

| 실행 위치 | 사용 API | 허용 범위 |
| --- | --- | --- |
| localhost, 127.0.0.1, ::1 | `/api` | 교사 인증 후 로컬 보관, PDF 판독, Ollama 분석·문체 검토 |
| HTTPS 온라인 도메인 | `/.netlify/functions/counseling-*` | 서버가 배정 관계를 확인한 일반 상담 작성·조회 |

`transport.ts`가 호스트에 따라 필요한 구현만 불러옵니다. 로컬 구현에는 클라우드 일반 AI 호출이 없습니다. 온라인 구현은 `local_only` 상담과 `record` 또는 `analysis`가 있는 사본의 전송을 거절하며, PDF 업로드·로컬 분석·분석 job 메서드는 네트워크 요청 전에 차단합니다.

온라인 인증은 기존 `dr_sess_v1` 세션의 `token`을 Bearer 헤더로 보냅니다. 표시 역할과 학생 목록은 세션 API 응답으로 정하며, 서버가 권한을 다시 검사합니다. 학생은 교사가 안내한 본인 전략을 읽고 내려받습니다. 교사는 **새 전략 → 학생 직접 추가**에서 이름·학번·학년도·학교급·학년을 입력하여 학생 회원가입이나 관리자 배정 없이 시작할 수 있습니다. 추가한 학생은 해당 교사의 담당 학생으로 등록되며 첫 전략을 만듭니다. 이미 배정된 학생을 선택하는 방식도 유지합니다. 학생 등록 이후 전략 생성이 실패하면 등록된 학생을 다시 사용합니다. 직접 추가는 학생 로그인 계정을 생성하거나 기존 회원·다른 교사의 학생을 자동 연결하지 않습니다. 회원 계정이 없는 학생에게는 확정된 학생 안내 PDF를 전달할 수 있습니다. 로그인 계정이 연결된 학생은 교사가 확정 후 별도 `publish` 요청으로 안내한 전략을 확인하며, 학생용 API 응답에서는 초안과 교사 참고 메모가 제외됩니다.

온라인 상단의 **로컬 실행기 다운로드**와 **사용안내**는 `/counseling/downloads/daeryun-counseling-local.zip`, `/counseling/guide.html`로 연결됩니다. 실제 ZIP과 안내 HTML은 운영 배포 단계에서 함께 제공해야 합니다.

## 상담 운영 관리

서버가 `user.can_manage: true`로 확인한 계정에만 **상담 운영 관리**를 표시합니다. 관리 전용 계정(`role: manager`)은 상담 본문 API를 호출하지 않고 관리 화면으로 바로 들어갑니다. 교사이면서 관리 권한이 있는 계정은 상담 화면과 관리 화면 사이를 이동합니다. `/counseling/?admin=1`도 같은 서버 권한 검사를 따릅니다.

관리 화면은 교직원의 학교 회원 승인 상태 확인, 학생 상담 참여 승인/해제, 학생 계정과 학년도별 학번 연결, 학생과 상담 교사의 배정/철회를 제공합니다. 승인된 교직원은 자동 이용하므로 교사 별도 참여 승인·해제 기능을 표시하지 않습니다. `GET counseling-admin`의 최소 목록만 사용하고 상담 본문을 불러오지 않습니다. 학생 참여 승인은 학교의 학생 회원 구분을 따르며, 학교 미승인 계정의 참여 승인·중복 학번·학교에서 승인되지 않은 교사의 배정을 막습니다. 담당 배정은 별도 상담 교사 승인 없이 학교의 승인된 교사 계정으로 설정합니다. 모든 변경은 대상과 변경 상태를 표시한 확인 창을 거쳐 POST로 저장하고 목록을 다시 조회합니다. 관리자 승격과 삭제 기능은 없습니다. 실제 권한 검사는 서버가 다시 수행합니다.

로컬 교사 로그인은 **대륜고 계정으로 연결** 버튼으로 고정된 `https://daeryun.life` 창을 엽니다. 승인된 교사가 표시된 PC 주소를 확인하고 **이 PC 연결**을 눌러야 인증이 전달됩니다. 로컬 창은 메시지의 정확한 origin과 자신이 연 팝업 창을 함께 검사한 뒤 로컬 서버에서 교사 권한을 재확인합니다. 연결 대상은 HTTP의 `127.0.0.1` 또는 `localhost` origin으로만 제한합니다. 학생·미승인 교사는 전달할 수 없습니다. 토큰을 URL, 클립보드, 로그에 넣지 않으며 학생부·상담 본문은 이 연결로 보내지 않습니다. 직접 토큰 입력은 고급 연결에 접어 두었습니다. 로그인하지 않은 경우 사용설명서 로그인은 별도 탭으로 열리므로 로그인 후 연결 창으로 돌아와 상태를 다시 확인합니다. 이 연결 화면이 운영 도메인에 배포되기 전에는 고급 연결을 사용할 수 있습니다.

온라인 일반 AI는 서버 AI, 개인 Gemini, 이 PC의 Ollama 중에서 선택합니다. 개인 키와 모델 설정은 `daeryun-counseling:ai:v1`에 이 도메인·브라우저 범위로 저장합니다. Gemini 키는 헤더로 보내며 URL·상담·백업에 넣지 않습니다. 개인 AI 입력에서는 구조화된 학생 이름과 학번을 제외합니다. 상담 본문에 직접 적은 개인정보까지 자동 제거하는 기능은 아닙니다. 외부 AI는 화면의 전송 확인 후 호출하며, 개인 Ollama는 loopback 주소와 로컬 모델만 허용합니다. 실패할 때 다른 제공자로 자동 전환하지 않습니다.

## 기록과 확인

저장 충돌(409)은 작성 중 초안을 유지하고 JSON 백업 및 최신 기록 불러오기를 제공합니다. 상담·회차 이동 시 저장하지 않은 변경을 확인합니다. 가져오기는 학년도·학번·학생 확인란을 거치며 기존 기록을 덮어쓰지 않습니다. 이전 확정은 새 사본의 현재 교사 확정으로 승계하지 않습니다.

PDF는 크기와 파일 서명을 확인한 후 서버로 전송합니다. 판독 항목, 빈칸·해당 없음·불확실 상태, 페이지 번호와 추출 근거를 표시합니다. 분석의 근거 링크는 해당 항목을 열어 줍니다. 원래 PDF 파일과 대조할 수 있도록 추출임을 표시하며, 내장 원본 PDF 뷰어는 포함하지 않습니다.

분석·문체 job은 진행 상태를 조회하고 서버에 취소를 요청합니다. 결과가 보류되거나 실패하면 오류를 표시합니다. 문체 검토의 `pending`은 교사가 직접 확인할 상태로 표시하며, 확인란을 선택해야 확정할 수 있습니다. `needs_revision`은 확정할 수 없습니다. 내용이 바뀌면 이전 검토를 현재 검토로 표시하지 않습니다. 로컬 합성 시연의 확정에는 실제 교사 검토가 아니라는 표시를 유지합니다.

로컬 PDF는 서버의 PDF 파일로, 온라인 PDF는 인증해 받은 UTF-8 HTML을 새 인쇄 창으로 열어 저장합니다. 내보내기에는 현재 선택한 `session_id`가 포함됩니다.

## 검증 범위

0.6.1 기준 통합 하네스 `harness/counseling-runs/20260914T021332204776Z/result.json`에서 학교 자료 일치, Python 115개 중 112개 통과·기존 권한 검사 3개 건너뜀, 클라우드 167개·프런트 핵심 79개·타입·빌드가 통과했습니다. 이후 인쇄 줄 나눔 보완의 클라우드 관련 회귀 58개와 합성 안내 문구의 로컬 관련 회귀 20개도 통과했습니다. 최종 모바일·미리보기 변경에 영향을 받은 Edge 20개와 타입 검사가 통과했으며, 초기 검사에서 통과한 비영향 18개를 포함해 전체 38개 시나리오 범위를 확인했습니다. 미리보기 포커스·내용 수정 버튼 노출·키보드 편집 복귀와 390px·320px 첫 화면에서 실행과제 제목·본문 첫줄 노출을 검사했습니다. 초기 38개 중 1개 실패와 수정 후 11개 재검증, 최종 20개 결과는 `_workspace/student-result-20260914/browser`에 구분해 보존했습니다.

실제 수록된 화법과 언어 평가과제와 학급 특색활동을 연결한 합성 학생 공통 사례로 로컬·온라인 PDF를 생성했습니다. 각각 3쪽이며 과제·기한·다음 점검이 첫쪽에 있고, 공개 문장 40줄·출처 2개·조건/AI 제한/적용 범위 5줄을 보존했습니다. 학생 비공개 자료 제외, 한글 렌더, 긴 문장과 페이지 경계를 확인했습니다. 개발 근거는 `_workspace/student-result-20260914/school-linked-pdf-validation.json`과 `school-linked-pdf-README.md`입니다. 초기 자동 연결 문구와 인쇄 실패본도 보존했습니다.

최종 UI 근거는 `_workspace/student-result-20260914/browser/result.json`과 `compact20-20260914T022420Z.stdout.log`입니다. 대표 화면은 `_workspace/student-result-20260914/screenshots/teacher-final-preview-activated-viewport.png`, `student-final-desktop-viewport.png`, `student-final-390-viewport.png`, `student-final-320-viewport.png`입니다. 이번 UI QA에서 실제 계정·로컬 모델·`local.spec`를 실행하지 않았으며 검사 서버 5178은 종료했습니다.

이 사례는 교사가 상담 후 문장을 다듬는 과정을 테스트 코드로 표현한 합성 시나리오이며 AI 자동 결과나 실제 교사 검토·학생 전달 사례가 아닙니다. 0.6.1에서 실제 모델을 새로 실행하지 않았습니다. 0.6.0의 Ollama 합성 검증 2회에서 남은 임의 필수 개수 제안, 실제 계정의 운영 저장·공개, 교사의 교육적 검토와 지속 사용 효과는 확인 범위를 구분합니다. 상세 구현·검증·한계는 `docs/50-final-student-result-quality.md`, 과거 모델 근거는 `docs/49-intuitive-strategy-release.md`에 있습니다. 0.6.1 배포 완료를 뜻하지 않습니다.

- 핵심 테스트: 호스트 구분, 기존 인증 토큰, 로컬·온라인 전송 차단, CSRF·revision·session ID, JSON·PDF 형식, 충돌, 개인 AI 키 헤더와 로컬 Ollama 제한.
- 브라우저 mock 테스트: 작성·분석·검토·확정·후속 회차, 409 초안 유지, 390px 모바일과 키보드 모달, job 취소·보류, 온라인 교사·학생 표시와 인쇄.
- 실제 로컬 통합: 실행 중인 **합성 시연 서버**에서 상담 생성, 제공 PDF 추출, 설치 모델 목록, 직접 검토와 합성 확정, PDF·JSON 다운로드, 학생 확인 후 가져오기와 후속 회차. 실제 학생 자료는 사용하지 않습니다.

실제 로컬 통합 테스트는 서버가 먼저 실행되어 있어야 합니다. 기본 브라우저는 설치된 Microsoft Edge이며 `PW_BROWSER_CHANNEL`로 변경할 수 있습니다.

```powershell
npx playwright test --config playwright.local.config.ts
```

서버가 시연 모드가 아니면 이 테스트는 건너뜁니다. 테스트는 합성 학번 `19991`의 새 상담·사본을 만듭니다. 실 Ollama 생성은 별도 백엔드 검증과 GPU 경합을 피하기 위해 이 브라우저 테스트에서 시작하지 않습니다. 온라인 운영 계정, 실제 서버 AI·개인 Gemini, 온라인 도메인에서 개인 Ollama의 브라우저 연결 허용은 배포 후 운영 환경에서 추가 확인해야 합니다.

로컬 계약은 `../../counseling_local/CONTRACT.md`, 온라인 계약은 `../../integrations/daeryun/API.md`를 따릅니다.
