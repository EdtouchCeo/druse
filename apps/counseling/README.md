# 학종 전략실 화면

**2026-09-17 · 0.9.0 구현·검증 기준, 배포용 구현·검증 기록.** 학생부를 교사 PC에서 분석하고 **학생부 분석 → 대학·학과 준비 → 질문 중심 학습**의 세 결과를 한 대시보드에서 읽는 Vue 3·TypeScript 화면입니다. 가상 분류 프로필을 사용한 실제 외부 모델 검증은 아래에 별도로 기록하며 실제 학교 계정의 전체 사용·운영 배포 완료와 구분합니다. 자세한 처리 경계는 [0.9.0 구현 문서](../../docs/61-admissions-dashboards-and-private-ai.md), 실제 화면 순서는 [교사용 이용안내](../../docs/학종_전략실_교사용_이용안내.md)를 참고합니다.

## 현재 작업 흐름

**학생 자료·로컬 분석 → 결과 대시보드**에서 작업합니다. 학생부 원본·추출·상세 분석은 교사 PC의 Ollama를 사용합니다. 대시보드의 첫 단계는 학습 이력·학업·진로·공동체·종합 진단을 보여 주며, 학업·진로·공동체 3역량과 학생부 8영역별 평가 관점도 설명합니다. 이는 프로젝트 지식베이스의 시행계획·학습 자료에 근거한 교육적 해석이며 대학 공통 배점표가 아닙니다. 분량과 근거가 부족한 분석은 PDF에서 **부분 분석 · 상세 근거 추가 필요**로 표시합니다.

**희망 대학·전공 추가**에서 대학·모집단위·전공·대입 학년도를 입력합니다. 새 준비 흐름의 전형 유형은 학생부종합으로 고정합니다. 최대 12행은 비교할 목표의 입력 한도이며 지원 횟수가 아닙니다. 새 자동 생성은 공개 자료가 연결된 **17개 대학과 29개 학과·분야 분류**를 지원합니다. 자유 입력이 이 범위와 연결되지 않으면 외부에 보내지 않고 안내합니다. 학과 분류는 대학별 실제 개설 학과·교육과정의 검증 목록이 아니므로 모집단위·캠퍼스·학년도·최종 모집요강을 확인해야 합니다. 이전 대학 안내의 상세 9개·공식 링크 235개 범위와 새 생성 지원 범위는 서로 다릅니다.

목표를 선택해 대학·학과별 학종 준비 전략을 생성하고, 같은 목표의 최신 결과로 질문 중심 학습을 이어갑니다. 각 결과는 다섯 상세 영역에 설명·이유·구체적인 방법·근거를 제시합니다. 대학·학과 조합별 PDF도 각각 다섯 본문 장으로 만들며 내용이 길면 여러 페이지로 이어집니다. 내용이 부족하거나 설명을 반복한 결과를 완성본으로 저장하지 않습니다. 새 생성은 `/preparation-strategy`, 상태 확인은 `/preparation-status`, 목표별 PDF는 `/preparation.pdf`를 사용합니다. 기존 `/strategy-draft`는 409로 새 흐름을 안내하며 과거 단일 전략은 **기존 전략 기록**에 보존합니다.

교사 관찰·상담·의견은 선택 입력입니다. 실제 상담 완료를 기록할 때만 상담일·학생 반응·합의한 방향을 확인합니다. 입력을 바꾸면 결과의 최신 여부를 해제하고 저장 후 다시 확인합니다. 현재 입력과 연결되지 않은 결과는 후속 생성·PDF 저장 전에 갱신해야 합니다. 확정·안내된 회차는 새 회차에서 수정합니다. 생성과 PDF 저장으로 교사 확정·학생 공개가 자동 실행되지는 않습니다.

시간 배분과 구체적인 실행 일정은 학생이 정합니다. 시간 상한·과제 진행 상태·점검일을 입력하지 않으며 이전 백업값은 보존합니다. 학교 과제의 실제 제한시간·분량·자료·제출 형식·AI 사용 조건은 그대로 지킵니다. 프로젝트 지식베이스의 실제 학교 과제·활동은 원문 출처와 조건을 유지한 채 로컬에서 전략에 연결합니다. 계획의 학년도·학년·선택 과목과 실제 운영 여부는 교사가 확인합니다.

## 개인정보와 외부 전략 생성

외부 AI에는 로컬에서 허용 목록으로 변환한 학습 분류와 공개 대학 자료만 보냅니다. 학생·교사·학교 이름, 학번·계정, 학생부 원문·이미지·추출 문장, 상세 분석 전체, 교사 관찰·상담·의견 원문, 로컬 파일명·경로는 전송하지 않습니다. 후속 질문 생성에는 검증된 앞 단계 연결 토큰을 사용합니다. 실제 학교 과제와 로컬 원문 근거는 PC에서 결과에 결합합니다.

기존 `cloudTransport.generalAi`의 서버·개인 Gemini·Ollama 경로는 **모두 네트워크 요청 전에 차단**합니다. 온라인 `counseling-ai`도 기존 일반 AI 실행을 409로 거절합니다. 자유서술 입력을 개인 키로 직접 보내는 예전 방식은 현재 사용 경로가 아닙니다. 새 외부 전략은 로컬 서버의 전용 요청과 승인된 서버 처리를 따릅니다.

원문·분석뿐 아니라 `session.preparation_reports`가 있는 사본은 온라인 저장·가져오기·공개 대상으로 보내지 않습니다. `privacy`를 바꾸거나 원문·분석을 제거해도 보고서의 로컬 근거·학교 활동·연결 토큰을 클라우드로 보낼 수 없습니다. 전체 JSON 백업은 교사 PC에서 보관하고 로컬로 복원합니다. 학생용 조회는 이 내부 묶음을 제외합니다.

## 실행과 빌드

Node 22.12 이상에서 이 폴더를 작업 위치로 사용합니다.

```powershell
npm ci --ignore-scripts
npm run dev
npm run build
npm test
npm run test:ui
```

개발 서버는 `127.0.0.1`로만 열리며 `/api`를 로컬 서버 `127.0.0.1:8765`로 연결합니다. 빌드 결과는 `dist/`, 서비스 경로는 `/counseling/`입니다. 로컬 Python 서버가 빌드를 제공하거나 통합 배포 단계에서 같은 경로로 복사합니다. 이 빌드 명령은 자동 배포하지 않습니다. OneDrive에서 전체 재귀 삭제를 피하도록 Vite `emptyOutDir: false`를 유지합니다. 현재 `dist/index.html`이 참조하는 자산을 사용해야 합니다.

학교 사용 설명서의 색상·글꼴·원본 교표를 사용하며 외부 이미지 요청 없이 표시합니다. 학교 자료와 분석 기준의 공유 JSON은 프런트·로컬 사본이 일치해야 합니다. 원본 학교 PDF나 실제 학생 자료를 실행 묶음에 자동 수집하지 않습니다.

이전 버전을 실행 중이면 저장·백업하고 기존 실행 창을 종료한 뒤 0.9.0 묶음의 **상담실_교사용.cmd**로 재시작합니다. 브라우저 새로고침은 실행 중인 서버를 교체하지 않습니다.

## 교사 계정과 PC 연결

학교 회원 승인이 완료된 교직원은 별도의 전략실 참여 승인 없이 이용합니다. 일반 온라인 로그인은 학교 인증 후 같은 탭의 `/counseling/`로 돌아옵니다. `dr_sess_v1` 세션의 만료 토큰은 갱신·재인증하며, 복귀 경로는 전략실로 제한하고 한 번 사용하면 지웁니다.

PC의 **대륜고 계정으로 연결**은 고정된 `https://daeryun.life` 인증 창을 엽니다. 이 `connect_local` 창에는 학생 목록·편집·관리 화면이 없습니다. 학교 로그인은 임시 창에서 진행하고 완료되면 닫히며, 기존 연결 창이 로그인 상태를 자동으로 확인합니다. 명시적인 **이 PC 연결** 후 PC에서 인증과 자료 조회가 성공하면 인증 창을 닫습니다. 실패·20초 응답 지연은 재시도를 안내합니다. 이전 실행 묶음은 성공 응답이 없어 인증 창을 직접 닫아야 할 수 있으므로 웹·로컬에 새 빌드가 함께 필요합니다.

PC 창과 인증 창은 메시지의 정확한 origin·열었던 창을 검사하고 로컬 서버가 승인 교사 권한을 다시 확인합니다. 대상은 HTTP `127.0.0.1` 또는 `localhost` origin만 허용합니다. 토큰은 URL·클립보드·로그에 넣지 않으며 학생부·상담 본문을 이 연결로 보내지 않습니다. 수동 토큰 입력은 고급 연결에 남습니다. 계정 연결은 온라인 기록과 로컬 기록의 병합·동기화가 아닙니다.

| 실행 위치 | API와 사용 범위 |
| --- | --- |
| localhost, 127.0.0.1, ::1 | `/api`: 로컬 보관·PDF 판독·Ollama 분석·분류 기반 외부 전략 요청·목표별 PDF |
| HTTPS 온라인 도메인 | `/.netlify/functions/counseling-*`: 계정 확인·담당 관계에 따른 기존 일반 기록 작성·조회 |

온라인 **학생 직접 추가**는 담당 학생과 첫 전략을 만들며 학생 로그인 계정을 자동 생성하거나 기존 다른 교사의 학생을 연결하지 않습니다. 계정이 연결된 학생의 온라인 안내는 참여 승인·담당 연결·교사 확정과 별도 `publish` 요청이 필요합니다. 로컬 결과는 필요한 PDF를 교사가 직접 전달합니다.

온라인 **로컬 실행기 다운로드**와 **사용안내**는 `/counseling/downloads/daeryun-counseling-local.zip`, `/counseling/guide.html`을 사용합니다. 파일·안내 HTML은 운영 배포에 함께 포함해야 합니다.

## 관리·저장·기존 기록

서버가 `user.can_manage: true`로 확인한 계정에만 **상담 운영 관리**를 표시합니다. 관리 전용 계정은 상담 본문을 조회하지 않고 관리 화면으로 들어갑니다. 학교 회원 승인 상태, 학생 참여 승인·해제, 학생 계정·학번 연결, 담당 배정·철회를 다룹니다. 관리자 승격·삭제 기능은 없으며 실제 권한은 서버에서 검사합니다.

저장 충돌(409)은 초안을 유지하고 JSON 백업·최신 기록 불러오기를 제공합니다. 학생·회차 이동 시 미저장 변경을 확인합니다. 가져오기는 학생 정보를 확인한 새 사본이며 이전 교사의 확정·공개·검토를 현재 확인으로 승계하지 않습니다. 현재 원본 재확인과 관련 결과 재생성이 필요합니다.

학생부 PDF는 파일 서명·20MB·80쪽 제한을 확인하고 교사 PC 서버로 보냅니다. 원문 항목의 기간·페이지·판독 상태와 분석 근거를 대조합니다. 원본 정정은 이전 분석을 무효화합니다. job의 진행·취소·실패를 표시하고 이전 성공 결과를 보존하며, 일부 생성 결과를 완성본으로 저장하지 않습니다.

기존 직접 작성 전략의 문체 검토·교사 확정·학생 안내 절차는 유지합니다. 검토의 `pending`은 교사 확인이 필요하고 `needs_revision`은 확정할 수 없습니다. 현재 내용이 바뀌면 이전 검토를 재사용하지 않습니다. 합성 시연의 확정은 실제 교사 검토와 구분합니다. 로컬 PDF는 서버 PDF로, 기존 온라인 PDF는 인증받은 HTML 인쇄로 저장하며 선택한 `session_id`를 명시합니다.

## 현재 검증 범위

프런트 단위 118개, 인증·대시보드 Edge 13개, 타입 검사·운영 빌드가 통과했습니다. Python 전체 323개 중 3개는 기존 환경 제약으로 건너뛰었습니다. UI 요청은 합성 응답으로 확인했으며 실제 계정·외부 AI 호출·운영 배포 확인과 구분합니다. 최신 실행 범위와 후속 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록합니다.

별도 가상 분류 프로필과 운영용 생성 함수로 실제 Gemini 3.6 Flash의 두 단계·총 열 장을 내용 검증했습니다. 실제 응답의 학종 준비·질문 중심 학습 PDF 각 10쪽도 확인했습니다. 이는 실제 학생 자료·운영 계정의 전체 흐름 검증이 아닙니다. 로컬 실제 응답 검증에서는 원문에 근거한 판단 10개를 보존하고 상세 기준과 본문 10쪽 PDF를 확인했습니다. 합성 자료의 검증이며 실제 학생은 교사의 원문 대조가 필요합니다.
