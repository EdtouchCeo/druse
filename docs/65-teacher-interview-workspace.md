# 교사 전용 학생부 모의면접

2026-09-29 · 1.1.0 초기 구현

1.1.1에서는 [분석 진행 상태 확인과 이어서 분석](66-analysis-recovery.md)을 추가했다. 새로고침 후 진행 중인 작업을 다시 확인하고, 중단된 분석의 검증 완료 구간을 재사용할 수 있다.

교사 PC에서 학생 한 명씩 학교생활기록부를 분석하고, 맞춤 질문·전사본 검토·학생 종합 보고서를 작성한다. 교사는 대륜고 계정으로 로컬 앱에 연결한 뒤 학생·회차를 선택하고 **학생부 모의면접** 메뉴를 연다.

## 이용 순서

1. 기존 **학생부 PDF 근거**에서 실제 학생부를 등록한다. 모의면접의 **학생부·질문**에서 원본을 확인한 기재를 선택하고 학생 작성 보충 설명을 저장한다.
2. **AI 분석·질문 생성**을 실행한다. 기재 분석과 질문별 인용을 대조하고 문항을 수정해 **면접에 사용**으로 채택한다. 질문지 PDF를 출력할 수 있다.
3. 면접을 별도로 녹음 또는 녹화하고 전사본을 작성한다. **전사본 검토**에서 TXT·DOCX·SRT·VTT 파일 또는 텍스트를 등록한다. 파일은 2MB 이하, 텍스트는 12만 자·600개 발화 이하이다.
4. **AI 전사본 사전 검토**를 실행한다. AI는 화자·질문/답변·전사 오류 의심과 학생부 대조 사항을 제안한다. 원음을 듣고 전사 정확성을 인증하는 기능은 아니다.
5. 교사가 화자·실제 발언을 확인·수정한다. 각 발화를 확인하거나, 사유를 적어 분석에서 제외한다. 검토 대기 발화는 평가 근거로 쓰지 않는다. **전사본 교사 검토 저장**을 누른다.
6. **종합 보고서**에서 AI 초안을 생성한다. 종합 의견·강점·보완점·진로 및 학업 계획·성찰·지도 계획을 편집하고 **교사 최종 의견**을 추가한다.
7. 교사 보완 내용을 저장한 뒤 근거를 확인해 확정한다. Word·PDF로 저장해 지도에 활용한다. AI 재생성은 새 판본을 추가하므로 교사가 편집한 이전 보고서가 남는다. 확정본을 수정할 때는 편집 사본을 만든다.

학생부와 전사본의 문장은 분석 자료로 취급한다. 문서 속 지시를 실행하지 않는다. 생성한 질문은 연습 문항이고, 대학의 실제 기출이나 공식 채점 결과가 아니다. 학생이 직접 접속하는 계정·화면, 앱 내 녹음·녹화·자동 전사는 구현 범위에 포함하지 않았다.

## 보고서와 저장

기재·학생 발화의 인용을 코드로 검증하고, 교사가 확인한 학생 발화가 없으면 보고서를 생성하지 않는다. 보고서에는 사용한 기재와 문답, 보류·제외 범위가 포함된다. AI 문장의 의미·개념 정확성은 교사가 별도로 판단한다.

면접 자료는 기존 비동기화 로컬 저장소의 별도 SQLite 테이블에 저장한다. 일반 상담 Case 본문이나 온라인 전략 전송 경로에 넣지 않는다. 교사 인증·CSRF·담당 학생 조회를 거치며, 면접 작업 중에는 다른 학생의 AI 작업을 시작할 수 없다. 작업 취소·입력 변경·교사 연결 변경 시 생성 중 결과를 현재 결과로 저장하지 않는다.

**면접 자료 백업**은 해당 회차의 현재 전사 원본·수정본, 보충 설명과 보고서 판본·근거 사본을 JSON으로 저장한다. 이전 전사 파일의 전체 저장 이력과 별도 녹음·영상, 학생부 원본 PDF 파일은 이 JSON에 포함하지 않는다. 원자료는 학교가 정한 로컬 보관·백업 절차를 따른다.

**면접 백업 복원**은 현재 선택한 학생의 동일한 학생부 기재가 있는 회차에서 사용한다. 학생 이름·학번·학년도를 확인하며, 전사본과 보충 설명을 복원하고 보고서는 미검증 사본으로 추가한다. 기존 보고서는 보존한다. 백업의 교사 확인·확정 표시는 현재의 승인으로 인정하지 않으므로 기재 확인과 AI·교사 전사 검토를 다시 진행한다. 복원 파일은 20MB 이하이다.

입력 자료가 바뀌면 기존 보고서에 **이전 자료 기준**을 표시한다. 과거 보고서의 인용은 생성 당시 사본을 사용한다. 전사 오류를 수정한 일을 학생의 역량 향상으로 자동 평가하지 않는다.

실제 학생 자료와 출력 보고서는 관리된 비동기화 위치에 보관한다. 사용 설명서에는 이용 방법만 게시한다. 녹음·녹화·전사 도구의 처리 장소는 해당 도구와 학교의 운영 절차에 따른다.

## 처리 범위와 오류

- 한 번에 기재 1~30개를 선택한다. 기재와 전사본을 묶음으로 처리하고 지나치게 큰 입력은 범위를 줄이도록 안내한다. 원문을 조용히 잘라내지 않는다.
- 화자 표기가 없으면 교사가 지정한다. 시간 정보가 없으면 발화 번호로 확인하며 시간을 만들어 넣지 않는다.
- JSON 형식·근거 인용 검사가 실패하면 생성 결과를 저장하지 않고 기존 자료를 유지한다. 설치된 로컬 모델의 응답 품질에 따라 재시도·모델 변경이 필요할 수 있다.
- 시연 모드는 제공하는 합성 PDF와 합성 전사본만 사용한다. 실제 자료는 교사 계정을 연결한 실행기에서 처리한다.

## 구현·검증 위치

- 로컬 도메인·파일 판독·근거 검증: `counseling_local/interview.py`
- 인증된 API 연결: `counseling_local/interview_api.py`
- Word·PDF·질문지 출력: `counseling_local/interview_export.py`
- 교사 화면: `apps/counseling/src/components/InterviewWorkspace.vue`
- 합성 자료 계약 검사: `tests/test_interview.py`
- 실제 로컬 API를 사용하는 브라우저 검사: `apps/counseling/tests/interview.spec.ts`

실제 학생 자료로 교육적 품질을 검수하는 단계와 운영 사이트 배포는 별도이다. 합성 자료의 기능 검사만으로 면접 평가 품질이나 합격 가능성을 보증하지 않는다.
