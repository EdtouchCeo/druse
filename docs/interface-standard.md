# 직관적인 입력·실행 화면 기준

2026-09-14 사용자 확정. 화면 설계·구현·검토에 적용하며 다른 앱의 UI를 승인 없이 일괄 변경하지 않는다.

1. 현재 작업과 다음 행동을 먼저 보여 준다. 주요 버튼과 필요한 입력을 긴 소개·설명보다 앞에 둔다. 빈 화면에서도 학생 선택, 자료 입력처럼 시작할 행동이 보인다.
2. 안내는 해당 행동을 이해하는 데 필요한 만큼만 쓴다. 라벨과 버튼이 이미 말한 내용을 설명 문단으로 반복하지 않는다. 기능 철학·전체 절차·설치·오류 대응의 상세 내용은 사용 매뉴얼에 둔다. 도움말은 매뉴얼의 해당 절로 연결한다.
3. 각 입력에 항목에 맞는 짧고 구체적인 예시를 제공한다. 항상 보이는 라벨은 유지하며 placeholder로 라벨을 대체하지 않는다. 예시는 실제 입력값·완료 기록으로 취급하거나 자동 저장·제출하지 않는다. 학생의 성적·경험·상담 반응을 예시에서 복사해 사실처럼 채우지 않는다.
4. 필수값, 형식·단위, 권한, 전송·보관 범위, 공개 조건은 관련 입력·버튼 가까이에 둔다. 설명을 줄여도 개인정보·로컬 전용 조건, 저장되지 않은 변경, 검토·확정·공개의 구분, 권한 차이를 숨기지 않는다.
5. 정상적인 비로그인·빈 상태는 다음 행동과 함께 중립적으로 안내한다. 실제 오류에는 원인과 복구 행동을 짧게 표시한다. 진행 상태·취소·저장 결과·충돌 복구는 사용자가 작업하는 위치에서 확인할 수 있어야 한다.
6. PC와 모바일에서 주요 행동을 찾을 수 있어야 한다. 한국어 어절과 제목의 줄바꿈, 긴 입력·본문, 가로 넘침, 키보드 이동 순서와 보이는 포커스, 라벨 연결을 실제 화면에서 확인한다. 설명을 줄이기 위해 글자 크기를 과도하게 줄이지 않는다.
7. 학생에게 전달하는 결과는 무엇을, 어떤 자료·방법으로, 어느 범위까지 할지와 확인할 산출물·다음 점검이 드러나야 한다. 학교 자료의 조건·출처와 학생의 실제 과목·시간을 반영한다. 빈 자료를 약점으로 판단하거나 계획을 수행 사실로 쓰지 않는다. 카드 순서·자동 추천을 교사의 확정 판단처럼 보이지 않게 한다.
8. 화면을 간결하게 바꾸면서 기능·권한·데이터 경계를 바꾸지 않는다. 저장·백업·복구·내보내기·동의·검토·확정·학생 안내, 온라인/로컬 구분과 교사/학생 권한은 기존 계약에 따라 유지한다. 학교 자료의 연도·대상·조건·출처는 해당 계획의 근거에서 확인할 수 있어야 한다.


상세 근거·전파 기록: 학생부관리 플랫폼의 `docs/48-intuitive-interface-standard.md`. 공통 문체 전문은 기존 `글쓰기_스타일가이드.md`를 그대로 참조한다. 매뉴얼의 상세 절차는 보존하되 업무 화면에는 현재 행동에 필요한 정보와 해당 매뉴얼 절로 가는 링크를 둔다.
